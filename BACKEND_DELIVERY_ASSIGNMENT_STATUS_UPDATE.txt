BACKEND: Delivery Assignment Status Update Flow
================================================

When a user changes the delivery status in the Delivery Assignments page, here's what happens:

FRONTEND CALL:
--------------
- Function: `handleStatusUpdate(assignmentId, newStatus)` in `delivery-assignments/page.tsx`
- API Call: `apiClient.updateDeliveryAssignment(assignmentId, { status: newStatus })`
- HTTP Method: PUT
- Endpoint: `/api/delivery-assignments/${assignmentId}`
- Request Body: { "status": "DELIVERED" or "NOT_DELIVERED" }

BACKEND ENDPOINT:
-----------------
PUT /api/delivery-assignments/:id

Expected Request Body:
{
  "status": "DELIVERED" | "NOT_DELIVERED"
}

WHAT SHOULD HAPPEN IN BACKEND:
------------------------------

1. Update Delivery Assignment Document:
   - Collection: `deliveryassignments` (or similar)
   - Update the `status` field in the delivery assignment document
   - Update `updated_at` timestamp
   - Optionally log who made the change and when

2. Update Related Documents (if applicable):
   
   a) If the delivery assignment is linked to a Request/Shipment Request:
      - Collection: `shipmentrequests` or `requests`
      - Update `delivery_status` field to match:
        * "DELIVERED" → `delivery_status: "DELIVERED"`
        * "NOT_DELIVERED" → `delivery_status: "PENDING"` or keep existing
      - Update `status` if delivery completes the request:
        * If status is "DELIVERED", may update request `status` to "COMPLETED"
   
   b) If the delivery assignment is linked to an Invoice:
      - Collection: `invoices`
      - Update `delivery_status` field
      - May update `payment_status` if COD payment is collected
   
   c) If the delivery assignment is linked to an Invoice Request:
      - Collection: `invoicerequests`
      - Update `delivery_status` field
      - May trigger status change to "COMPLETED" if all conditions are met
   
   d) **CRITICAL: Update related Booking's shipment_status:**
      - Collection: `bookings`
      - When status is "DELIVERED", update the booking's `shipment_status` to "DELIVERED"
      - This ensures the status appears in the Review Requests page (Cargo Status Management)
      - Find booking by `invoice_id` (delivery assignment has `invoice_id`, booking also has `invoice_id`)
      - Update: `booking.shipment_status = "DELIVERED"` when delivery assignment status = "DELIVERED"
      - This is the key connection that makes the status visible in `/dashboard/review-requests`

3. Update Driver Assignment (if applicable):
   - May update driver's delivery statistics
   - Track delivery completion rate

4. Send Notifications (optional):
   - Notify customer about delivery status
   - Notify operations team
   - Update any tracking systems

BACKEND IMPLEMENTATION EXAMPLE:
-------------------------------

```javascript
// PUT /api/delivery-assignments/:id
router.put('/delivery-assignments/:id', authenticateToken, async (req, res) => {
  try {
    const { id } = req.params;
    const { status } = req.body;
    
    // Validate status
    if (!['DELIVERED', 'NOT_DELIVERED'].includes(status)) {
      return res.status(400).json({ 
        success: false, 
        error: 'Invalid status. Must be DELIVERED or NOT_DELIVERED' 
      });
    }
    
    // Update delivery assignment
    const assignment = await DeliveryAssignment.findByIdAndUpdate(
      id,
      { 
        status: status,
        updated_at: new Date(),
        updated_by: req.user.id // from auth token
      },
      { new: true }
    );
    
    if (!assignment) {
      return res.status(404).json({ 
        success: false, 
        error: 'Delivery assignment not found' 
      });
    }
    
    // Update related request if linked
    if (assignment.request_id) {
      await ShipmentRequest.findByIdAndUpdate(
        assignment.request_id,
        { 
          delivery_status: status === 'DELIVERED' ? 'DELIVERED' : 'PENDING',
          updated_at: new Date()
        }
      );
      
      // If delivered, check if request should be marked as completed
      if (status === 'DELIVERED') {
        const request = await ShipmentRequest.findById(assignment.request_id);
        // Check if all conditions are met for completion
        // (e.g., invoice generated, payment collected, etc.)
        // If yes, update request.status to 'COMPLETED'
      }
    }
    
    // Update related invoice if linked
    if (assignment.invoice_id) {
      await Invoice.findByIdAndUpdate(
        assignment.invoice_id,
        { 
          delivery_status: status === 'DELIVERED' ? 'DELIVERED' : 'PENDING',
          updated_at: new Date()
        }
      );
    }
    
    // Update related invoice request if linked
    if (assignment.invoice_id) {
      // Find invoice request by invoice_id
      const invoice = await Invoice.findById(assignment.invoice_id);
      if (invoice && invoice.invoice_request_id) {
        await InvoiceRequest.findByIdAndUpdate(
          invoice.invoice_request_id,
          { 
            delivery_status: status === 'DELIVERED' ? 'DELIVERED' : 'PENDING',
            updated_at: new Date()
          }
        );
      }
    }
    
    // CRITICAL: Update related Booking's shipment_status
    // This makes the status appear in Review Requests page (Cargo Status Management)
    if (assignment.invoice_id && status === 'DELIVERED') {
      // Find booking(s) that have this invoice_id
      await Booking.updateMany(
        { invoice_id: assignment.invoice_id },
        { 
          shipment_status: 'DELIVERED',
          updated_at: new Date()
        }
      );
      
      // Alternative: If booking is linked via request_id instead
      if (assignment.request_id) {
        // Find bookings linked to the same request
        await Booking.updateMany(
          { 
            $or: [
              { request_id: assignment.request_id },
              { 'request_id._id': assignment.request_id }
            ]
          },
          { 
            shipment_status: 'DELIVERED',
            updated_at: new Date()
          }
        );
      }
    }
    
    res.json({
      success: true,
      data: assignment,
      message: 'Delivery assignment status updated successfully'
    });
    
  } catch (error) {
    console.error('Error updating delivery assignment:', error);
    res.status(500).json({ 
      success: false, 
      error: 'Failed to update delivery assignment' 
    });
  }
});
```

WHERE THE STATUS IS REFLECTED:
-------------------------------

1. **Delivery Assignment Document** (`deliveryassignments` collection):
   - `status` field: "DELIVERED" or "NOT_DELIVERED"
   - `updated_at` timestamp
   - `updated_by` user ID

2. **Shipment Request Document** (`shipmentrequests` or `requests` collection):
   - `delivery_status` field: Updated to match assignment status
   - `status` field: May change to "COMPLETED" if delivery completes the request

3. **Invoice Document** (`invoices` collection):
   - `delivery_status` field: Updated to match assignment status

4. **Invoice Request Document** (`invoicerequests` collection):
   - `delivery_status` field: Updated to match assignment status
   - `status` field: May change to "COMPLETED" if all conditions are met

5. **Booking Document** (`bookings` collection) - **CRITICAL FOR REVIEW REQUESTS PAGE:**
   - `shipment_status` field: Updated to "DELIVERED" when delivery assignment status = "DELIVERED"
   - This is what makes the status appear in `/dashboard/review-requests` (Cargo Status Management)
   - Find booking by matching `invoice_id` or `request_id` from delivery assignment
   - **This is the key connection that syncs delivery assignment status with review-requests page**

6. **Driver Statistics** (if tracked):
   - Delivery completion count
   - Delivery success rate

IMPORTANT NOTES:
----------------
- **CRITICAL:** When delivery assignment status is set to "DELIVERED", the related booking's `shipment_status` MUST be updated to "DELIVERED"
- This ensures the status automatically appears in the Review Requests page (Cargo Status Management) at `/dashboard/review-requests`
- The booking can be found by matching `invoice_id` or `request_id` from the delivery assignment
- The status update should be atomic (use transactions if updating multiple documents)
- Consider adding validation to prevent invalid status transitions
- Log all status changes for audit purposes
- Consider adding webhooks or notifications for status changes
- Ensure proper error handling if related documents don't exist
- **Test:** After updating delivery assignment to DELIVERED, verify the booking's shipment_status is updated and appears in review-requests page
