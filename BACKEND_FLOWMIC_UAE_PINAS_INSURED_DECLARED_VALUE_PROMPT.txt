BACKEND PROMPT: Declared Value Input for FLOWMIC UAE to PINAS Insured Shipments

PRIORITY: HIGH - Required for Operations Verification Workflow

================================================================================
REQUIREMENT OVERVIEW
================================================================================

When Operations classifies a shipment as FLOWMIC and the service is UAE to PINAS 
with insured = true in the database, the system must:
1. Display a declared value input field in the verification form
2. Require Operations to enter the declared amount
3. Save the declared value entered by Operations to the database

================================================================================
TRIGGER CONDITIONS
================================================================================

The declared value field should be shown and required when ALL of the following are true:

1. Shipment Classification = 'FLOWMIC'
   - Check: verification.shipment_classification === 'FLOWMIC'
   - OR: verification.boxes[].classification === 'FLOWMIC'

2. Service Code = UAE to PINAS
   - Check: service_code includes 'UAE_TO_PINAS' (case-insensitive)
   - OR: service_code includes 'UAE_TO_PH' (case-insensitive)
   - Examples: 'UAE_TO_PINAS', 'UAE_TO_PINAS_AIR', 'UAE_TO_PH_SEA', etc.

3. Insured = true (in database)
   - Check: request.insured === true
   - OR: request.booking.insured === true
   - OR: request.request_id.insured === true
   - OR: request.request_id.booking.insured === true
   - Note: This must be checked from the database, not from form input

================================================================================
FRONTEND BEHAVIOR
================================================================================

The frontend will:
1. Check if classification is FLOWMIC
2. Check if service is UAE_TO_PINAS
3. Check if insured = true in database (from request/booking)
4. If all conditions met, display declared value input field
5. Require user to enter declared value
6. Send declared_value to backend when verification is submitted

================================================================================
BACKEND REQUIREMENTS
================================================================================

1. VERIFICATION UPDATE ENDPOINT:
   PUT /api/invoice-requests/:id/verification

   When the above conditions are met:
   - Accept declared_value in request body
   - Validate that declared_value is provided and is a positive number
   - Save declared_value to verification.declared_value
   - Set verification.insured = true (if not already set)

   Request Body Example:
   {
     "shipment_classification": "FLOWMIC",
     "declared_value": 5000.00,  // Required when FLOWMIC + UAE_TO_PINAS + insured
     "insured": true,
     // ... other verification fields ...
   }

2. VALIDATION LOGIC:
   ```javascript
   // Check conditions
   const isFlowmic = verification.shipment_classification === 'FLOWMIC' ||
                     verification.boxes?.some(box => box.classification === 'FLOWMIC');
   
   const isUaeToPinas = serviceCode.toUpperCase().includes('UAE_TO_PINAS') ||
                        serviceCode.toUpperCase().includes('UAE_TO_PH');
   
   const isInsured = request.insured === true ||
                    request.booking?.insured === true ||
                    request.request_id?.insured === true ||
                    request.request_id?.booking?.insured === true;
   
   // If all conditions met, declared_value is required
   if (isFlowmic && isUaeToPinas && isInsured) {
     if (!declared_value || declared_value <= 0) {
       return {
         success: false,
         error: 'Declared value is required for FLOWMIC UAE to PINAS insured shipments'
       };
     }
   }
   ```

3. DATA STORAGE:
   - Store declared_value in verification.declared_value
   - Type: Number (Float)
   - Required: Yes (when conditions are met)
   - Format: Decimal with 2 decimal places (e.g., 5000.00)

4. INSURANCE CHARGE CALCULATION:
   - Insurance charge = declared_value × 0.01 (1% of declared value)
   - This should be calculated and stored when invoice is generated
   - Example: declared_value = 5000.00, insurance_charge = 50.00

================================================================================
DATABASE SCHEMA
================================================================================

The invoice_requests collection verification object should include:

```javascript
verification: {
  // ... existing fields ...
  shipment_classification: String,  // 'FLOWMIC' or 'COMMERCIAL'
  declared_value: Number,            // Required when FLOWMIC + UAE_TO_PINAS + insured
  insured: Boolean,                  // Should be true when declared_value is set
  // ... other fields ...
}
```

================================================================================
API ENDPOINT UPDATES
================================================================================

1. PUT /api/invoice-requests/:id/verification
   
   Validation:
   - If FLOWMIC + UAE_TO_PINAS + insured = true:
     * declared_value MUST be provided
     * declared_value MUST be > 0
     * Return error if missing or invalid
   
   Response:
   - Include declared_value in verification object
   - Include insured flag (set to true)

2. GET /api/invoice-requests/:id
   
   Response:
   - Include verification.declared_value if present
   - Include verification.insured if present
   - Include request.insured or booking.insured for frontend to check

ERROR HANDLING
================================================================================

When conditions are met but declared_value is missing or invalid:

```javascript
{
  "success": false,
  "error": "Declared value is required for FLOWMIC UAE to PINAS insured shipments. Please enter a valid declared value (must be greater than 0)."
}
```

When declared_value is provided but conditions are not met:
- Still accept and store declared_value (for backward compatibility)
- Do not require it

================================================================================

2. The frontend will check insured status from:
   - request.insured
   - request.booking.insured
   - request.request_id.insured
   - request.request_id.booking.insured
