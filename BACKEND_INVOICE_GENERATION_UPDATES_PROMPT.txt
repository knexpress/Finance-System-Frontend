BACKEND: Invoice Generation Updates - Pickup Charge and Insurance
===================================================================

REQUIREMENT:
------------
Three changes have been made to the invoice generation flow in the frontend:

1. **Pickup Charge now accepts 0 as a valid value**
2. **Delivery Charge now accepts 0 as a valid value**
3. **Fixed amount insurance option has been removed** (only "1% of declared value" remains)

BACKEND CHANGES REQUIRED:
-------------------------

1. **Pickup Charge Validation:**
   - **Current behavior:** Backend may be rejecting 0 as an invalid pickup charge
   - **Required change:** Accept 0 as a valid pickup charge value
   - **Reason:** Users may want to set pickup charge to 0 for certain scenarios
   
   **Validation should be:**
   ```javascript
   // OLD (if exists):
   if (pickupCharge < 0 || pickupCharge === 0) {
     return error; // ❌ Rejects 0
   }
   
   // NEW:
   if (pickupCharge < 0) {
     return error; // ✅ Accepts 0
   }
   
   // Or simply:
   if (pickupCharge < 0 || isNaN(pickupCharge)) {
     return error; // ✅ Accepts 0 and any positive number
   }
   ```

2. **Delivery Charge Validation:**
   - **Current behavior:** Backend may be rejecting 0 as an invalid delivery charge
   - **Required change:** Accept 0 as a valid delivery charge value
   - **Reason:** Users may want to set delivery charge to 0 for certain scenarios
   
   **Validation should be:**
   ```javascript
   // OLD (if exists):
   if (deliveryCharge < 0 || deliveryCharge === 0) {
     return error; // ❌ Rejects 0
   }
   
   // NEW:
   if (deliveryCharge < 0) {
     return error; // ✅ Accepts 0
   }
   
   // Or simply:
   if (deliveryCharge < 0 || isNaN(deliveryCharge)) {
     return error; // ✅ Accepts 0 and any positive number
   }
   ```

3. **Insurance Option:**
   - **Current behavior:** Backend may accept "fixed" as an insurance option
   - **Required change:** Remove support for "fixed" insurance option
   - **Allowed values:** Only "none" or "percent" (1% of declared value)
   
   **Validation should be:**
   ```javascript
   // OLD (if exists):
   if (insuranceOption === 'fixed') {
     // Handle fixed insurance (mobile 300, laptop 450, or custom)
   }
   
   // NEW:
   // Remove fixed insurance handling entirely
   // Only support:
   // - 'none': No insurance
   // - 'percent': 1% of declared value
   ```

API ENDPOINTS AFFECTED:
-----------------------

1. **POST /api/invoices** (or similar invoice creation endpoint)
   - Accept `pickupCharge: 0` as valid
   - Accept `deliveryCharge: 0` as valid
   - Reject `insuranceOption: 'fixed'` if sent (should not happen from frontend, but validate anyway)

2. **PUT /api/invoices/:id** (if invoice updates are allowed)
   - Same validation rules apply

EXAMPLE IMPLEMENTATION:
-----------------------

```javascript
// Invoice creation/update validation
router.post('/invoices', authenticateToken, async (req, res) => {
  try {
    const { pickupCharge, insuranceOption, insuranceCharge, ...otherData } = req.body;
    
    // Validate pickup charge - accept 0 as valid
    if (pickupCharge !== undefined && pickupCharge !== null) {
      const pickupChargeNum = parseFloat(pickupCharge);
      if (isNaN(pickupChargeNum) || pickupChargeNum < 0) {
        return res.status(400).json({
          success: false,
          error: 'Pickup charge must be 0 or greater'
        });
      }
      // pickupChargeNum === 0 is now valid ✅
    }
    
    // Validate delivery charge - accept 0 as valid
    if (deliveryCharge !== undefined && deliveryCharge !== null) {
      const deliveryChargeNum = parseFloat(deliveryCharge);
      if (isNaN(deliveryChargeNum) || deliveryChargeNum < 0) {
        return res.status(400).json({
          success: false,
          error: 'Delivery charge must be 0 or greater'
        });
      }
      // deliveryChargeNum === 0 is now valid ✅
    }
    
    // Validate insurance option - only 'none' or 'percent'
    if (insuranceOption && !['none', 'percent'].includes(insuranceOption)) {
      return res.status(400).json({
        success: false,
        error: 'Invalid insurance option. Only "none" or "percent" are allowed'
      });
    }
    
    // If insurance is 'percent', validate declared amount exists
    if (insuranceOption === 'percent') {
      const declaredAmount = req.body.declaredAmount || req.body.declared_amount;
      if (!declaredAmount || declaredAmount <= 0) {
        return res.status(400).json({
          success: false,
          error: 'Declared amount is required for percentage-based insurance'
        });
      }
      // Calculate 1% of declared amount
      const calculatedInsurance = parseFloat((declaredAmount * 0.01).toFixed(2));
      // Use calculatedInsurance instead of insuranceCharge from request
    }
    
    // Continue with invoice creation...
    const invoice = await Invoice.create({
      ...otherData,
      pickupCharge: pickupChargeNum || 0, // Allow 0
      deliveryCharge: deliveryChargeNum || 0, // Allow 0
      insuranceOption: insuranceOption || 'none',
      insuranceCharge: insuranceOption === 'percent' ? calculatedInsurance : 0,
      // ... other fields
    });
    
    res.json({
      success: true,
      data: invoice
    });
    
  } catch (error) {
    console.error('Error creating invoice:', error);
    res.status(500).json({
      success: false,
      error: 'Failed to create invoice'
    });
  }
});
```

DATABASE SCHEMA:
---------------
No schema changes required. The database should already support:
- `pickupCharge` as a number (including 0)
- `insuranceOption` as a string (but only 'none' or 'percent' should be used now)

MIGRATION (if needed):
----------------------
If existing invoices have `insuranceOption: 'fixed'`, you may want to:
1. Keep them as-is (for historical data)
2. Or migrate them to 'none' or 'percent' based on business logic

IMPORTANT NOTES:
---------------
- Pickup charge of 0 is now a valid business case
- Delivery charge of 0 is now a valid business case
- Fixed amount insurance option is completely removed from the system
- Only percentage-based insurance (1% of declared value) is supported
- Backend should validate and reject any attempts to use 'fixed' insurance option
- Ensure all invoice-related endpoints follow these validation rules
- Both pickup and delivery charges can be 0, which may indicate free pickup/delivery services
