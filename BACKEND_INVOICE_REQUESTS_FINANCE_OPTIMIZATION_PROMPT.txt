BACKEND PROMPT: Optimize Invoice Requests API for Finance Department - VERIFIED Status Filtering

PRIORITY: HIGH - Performance Critical
TARGET: Sub-100ms response time even with 1000+ entries

================================================================================
REQUIREMENT
================================================================================

When the Finance department accesses the invoice requests page, the backend MUST:
1. Only return invoice requests with status = 'VERIFIED'
2. Optimize the query to achieve sub-100ms response time even with 1000+ entries
3. Use database indexes and query optimization techniques
4. Implement efficient pagination if needed

================================================================================
CURRENT BEHAVIOR
================================================================================

The frontend now sends a status filter parameter when Finance department accesses the page:
- GET /api/invoice-requests?status=VERIFIED&page=1&limit=50&fields=...

The backend should:
1. Filter at database level (NOT in application code)
2. Use indexed queries
3. Return only VERIFIED status entries
4. Exclude cancelled shipments (delivery_status !== 'CANCELLED')

================================================================================
OPTIMIZATION REQUIREMENTS
================================================================================

1. DATABASE INDEXING:
   - Create compound index on: { status: 1, delivery_status: 1, createdAt: -1 }
   - This allows fast filtering and sorting
   - Index should be created on the invoice_requests collection

2. QUERY OPTIMIZATION:
   - Use MongoDB find() with status filter at database level
   - Example: db.invoice_requests.find({ status: 'VERIFIED', delivery_status: { $ne: 'CANCELLED' } })
   - Use projection to return only requested fields (fields parameter)
   - Use lean() or equivalent to return plain objects (faster than Mongoose documents)

3. PAGINATION:
   - Implement efficient pagination using skip() and limit()
   - Consider using cursor-based pagination for better performance with large datasets
   - Return pagination metadata: { total, pages, currentPage, limit }

4. FIELD PROJECTION:
   - When fields parameter is provided, only return those fields
   - Reduces data transfer and improves performance
   - Use MongoDB projection: { field1: 1, field2: 1, ... }

5. EXCLUSION OF CANCELLED:
   - Exclude entries where:
     - delivery_status === 'CANCELLED'
     - request_id.status === 'CANCELLED' (if populated)
     - request_id.delivery_status === 'CANCELLED' (if populated)

================================================================================
EXPECTED QUERY STRUCTURE
================================================================================

MongoDB Query (example):
```javascript
const query = {
  status: 'VERIFIED',
  delivery_status: { $ne: 'CANCELLED' }
};

// If request_id is populated, also exclude cancelled related requests
// This should be handled in aggregation pipeline or separate query

const projection = fields ? 
  fields.reduce((acc, field) => {
    acc[field] = 1;
    return acc;
  }, {}) : {};

const options = {
  skip: (page - 1) * limit,
  limit: limit,
  sort: { createdAt: -1 } // Most recent first
};

const results = await InvoiceRequest.find(query, projection, options).lean();
```
