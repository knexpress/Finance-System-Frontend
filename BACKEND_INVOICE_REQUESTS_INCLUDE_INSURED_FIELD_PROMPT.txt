BACKEND PROMPT: Ensure Insured Field is Always Included in Invoice Requests API Response

CONTEXT:
The invoice requests API endpoint (`/invoice-requests`) supports field filtering via the `fields` query parameter. However, the `insured` field must always be included in the response, even when field filtering is used, because it's required for:
1. Displaying insured declared value in the invoice requests UI
2. Showing insurance information in the verification form
3. Calculating insurance charges during invoice generation

CURRENT ISSUE:
When the frontend requests specific fields using the `fields` query parameter, the `insured` field is not being returned, even though it exists in the database at the top level of the invoice request document.

DATABASE STRUCTURE:
Based on the invoice request collection, the `insured` field is stored at the top level:
```javascript
{
  _id: ObjectId,
  invoice_number: "INV-000068",
  tracking_code: "AEFCE5ZMZB83H3",
  service_code: "UAE_TO_PH",
  // ... other fields ...
  insured: true,  // <-- This field is at the top level
  status: "IN_PROGRESS",
  // ... other fields ...
  booking_snapshot: { ... },
  booking_data: { ... }
}
```

REQUIREMENTS:
1. **Always Include Insured Field**: The `insured` field must always be included in the API response, regardless of the `fields` query parameter. If field filtering is used, add `insured` to the list of fields to return.

2. **Include Related Fields**: Also ensure these related fields are always included when field filtering is used:
   - `insured` (top-level boolean)
   - `declaredAmount` or `declared_amount` (top-level)
   - `booking` (object, may contain insured)
   - `booking_snapshot` (object, may contain insured)
   - `booking_data` (object, may contain insured)
   - `sender_delivery_option` (string)
   - `receiver_delivery_option` (string)

3. **Nested Insured Fields**: Also check for insured in nested structures:
   - `verification.insured` (if exists)
   - `request_id.insured` (if request_id is populated)
   - `request_id.booking.insured` (if request_id.booking is populated)
   - `request_id.sender.insured` (if request_id.sender is populated)

4. **Backward Compatibility**: If the `fields` parameter is not provided, return all fields as usual. If `fields` is provided, ensure the insured-related fields listed above are always included in addition to the requested fields.

5. **Response Format**: The API should return the invoice request objects with the `insured` field at the top level, matching the database structure.

IMPLEMENTATION SUGGESTION:
```javascript
// Pseudo-code for the backend implementation
function getInvoiceRequests(fields, filters, pagination) {
  // Define required fields that must always be included
  const requiredFields = [
    'insured',
    'declaredAmount',
    'declared_amount',
    'booking',
    'booking_snapshot',
    'booking_data',
    'sender_delivery_option',
    'receiver_delivery_option'
  ];
  
  // If fields parameter is provided, merge with required fields
  let fieldsToSelect = fields;
  if (fields && Array.isArray(fields)) {
    fieldsToSelect = [...new Set([...fields, ...requiredFields])];
  }
  
  // Query database with field selection
  const query = InvoiceRequest.find(filters);
  if (fieldsToSelect) {
    const selectObject = {};
    fieldsToSelect.forEach(field => {
      selectObject[field] = 1;
    });
    query.select(selectObject);
  }
  
  // Execute query with pagination
  // ... rest of implementation
}
```
