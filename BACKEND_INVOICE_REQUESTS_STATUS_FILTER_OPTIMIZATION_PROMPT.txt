BACKEND PROMPT: Optimize Invoice Requests API with Status Filtering and Field Projection

PRIORITY: HIGH - Performance Critical
TARGET: Sub-100ms response time even with 1000+ entries per status

================================================================================
REQUIREMENT OVERVIEW
================================================================================

The frontend now includes a status filter dropdown that allows users to filter 
invoice requests by status. The backend must:
1. Support status filtering via query parameter
2. Use field projection to return only required fields
3. Optimize queries for each status filter
4. Ensure sub-100ms response time even with 1000+ entries

STATUS FILTERING REQUIREMENTS
================================================================================

1. STATUS PARAMETER HANDLING:
   - `status=all` or no status parameter: Return all statuses (respect department filters)
   - `status=DRAFT`: Return only DRAFT status
   - `status=SUBMITTED`: Return only SUBMITTED status
   - `status=IN_PROGRESS`: Return only IN_PROGRESS status
   - `status=VERIFIED`: Return only VERIFIED status
   - `status=COMPLETED`: Return only COMPLETED status
   - `status=CANCELLED`: Return only CANCELLED status

2. DATABASE QUERY OPTIMIZATION:
   ```javascript
   // Example MongoDB query
   const query = {};
   
   // Apply status filter
   if (status && status !== 'all') {
     query.status = status;
   }
   
   // Apply field projection
   const projection = {};
   if (fields && fields.length > 0) {
     fields.forEach(field => {
       // Handle nested fields (e.g., verification.actual_weight)
       if (field.includes('.')) {
         const [parent, child] = field.split('.');
         if (!projection[parent]) projection[parent] = {};
         projection[parent][child] = 1;
       } else {
         projection[field] = 1;
       }
     });
   }
   
   // Use index for status filtering
   const results = await InvoiceRequest.find(query, projection)
     .sort({ createdAt: -1 })
     .skip((page - 1) * limit)
     .limit(limit)
     .lean(); // Use lean() for faster queries
   ```

3. INDEXING REQUIREMENTS:
   - Create compound index: { status: 1, createdAt: -1 }
   - This allows fast filtering by status and sorting by date
   - Index should be created on invoice_requests collection

EXAMPLE IMPLEMENTATION
================================================================================

```javascript
// GET /api/invoice-requests
async function getInvoiceRequests(req, res) {
  try {
    const page = parseInt(req.query.page) || 1;
    const limit = Math.min(parseInt(req.query.limit) || 50, 500);
    const status = req.query.status;
    const fields = req.query.fields ? req.query.fields.split(',') : [];
    
    // Build query
    const query = {};
    if (status && status !== 'all') {
      query.status = status;
    }
    
    // Build projection
    const projection = buildProjection(fields);
    
    // Execute query with pagination
    const [data, total] = await Promise.all([
      InvoiceRequest.find(query, projection)
        .sort({ createdAt: -1 })
        .skip((page - 1) * limit)
        .limit(limit)
        .lean(),
      InvoiceRequest.countDocuments(query)
    ]);
    
    // Build pagination metadata
    const pages = Math.ceil(total / limit);
    const pagination = {
      page,
      limit,
      total,
      pages,
      hasNextPage: page < pages,
      hasPreviousPage: page > 1,
      nextPage: page < pages ? page + 1 : null,
      previousPage: page > 1 ? page - 1 : null,
      startRecord: (page - 1) * limit + 1,
      endRecord: Math.min(page * limit, total),
      summary: `Showing ${(page - 1) * limit + 1}-${Math.min(page * limit, total)} of ${total} invoice requests`,
      displayText: `${(page - 1) * limit + 1}-${Math.min(page * limit, total)} of ${total}`
    };
    
    res.json({
      success: true,
      data,
      pagination
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      error: error.message
    });
  }
}

function buildProjection(fields) {
  if (!fields || fields.length === 0) {
    return {}; // Return all fields if none specified
  }
  
  const projection = { _id: 1 }; // Always include _id
  
  fields.forEach(field => {
    if (field.includes('.')) {
      // Handle nested fields
      const [parent, child] = field.split('.');
      if (!projection[parent]) {
        projection[parent] = {};
      }
      projection[parent][child] = 1;
    } else {
      projection[field] = 1;
    }
  });
  
  return projection;
}
```

================================================================================
IMPORTANT NOTES
================================================================================

1. Field projection is OPTIONAL but HIGHLY RECOMMENDED:
   - If fields parameter not provided, return all fields (backward compatibility)
   - If fields parameter provided, return only those fields

2. Status filtering is OPTIONAL:
   - If status parameter not provided, return all statuses (or department default)
   - If status='all', return all statuses

3. Always use indexes:
   - Status filtering requires index on status field
   - Sorting requires index on createdAt field
   - Compound index { status: 1, createdAt: -1 } covers both

4. Use lean() queries:
   - Mongoose lean() returns plain objects (faster than documents)
   - Reduces memory usage
   - Improves query performance

5. Optimize count query:
   - Use countDocuments() with same query
   - Use index for fast counting
   - Consider caching counts for frequently accessed statuses
