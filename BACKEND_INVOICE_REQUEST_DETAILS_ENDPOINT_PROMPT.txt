# Backend Implementation: Get Invoice Request Details Endpoint

## Overview
Create a new endpoint that fetches a complete invoice request record with all verification, booking, and shipment data when a user clicks the "View" button in the invoice generation dialog. This endpoint should return the full invoice request data including all nested information from related collections.

## Endpoint Specification

### Route
```
GET /api/invoice-requests/:id/details
```

### Purpose
This endpoint is specifically designed to fetch complete invoice request data with all nested information when a Finance user wants to view full shipment details before generating an invoice. Unlike the regular `GET /api/invoice-requests/:id` endpoint, this one should:
1. Return ALL data including full verification object with all fields
2. Include complete booking/shipment data if linked
3. Include all box details with dimensions, classifications, etc.
4. Include all weight calculations (actual, volumetric, chargeable)
5. Include all rate and pricing information
6. Return data in a format that matches the frontend expectations

### Request
- **Method**: GET
- **URL**: `/api/invoice-requests/:id/details`
- **Parameters**: 
  - `id` (path parameter) - The invoice request ID

## Implementation Requirements

### 1. Data Population
The endpoint should populate/join the following related data:
- **Verification Data**: Full verification object with all fields including:
  - Weight calculations (actual_weight, volumetric_weight, total_vm, chargeable_weight)
  - Weight type (ACTUAL/VOLUMETRIC)
  - Calculated rate
  - All verification fields (agents_name, shipment_classification, cargo_service, rate_bracket, etc.)
  - All box details with dimensions and classifications
- **Request ID Data**: If invoice request has a linked request_id, populate:
  - Full request object
  - Shipment data (weight_type, number_of_boxes, volumetric_weight, chargeable_weight)
  - Verification data from request
- **Booking Data**: If invoice request has a linked booking, include booking details

### 2. Field Mapping
Ensure the following fields are returned (check multiple possible locations):
- **Weight Type**: `verification.weight_type` OR `request_id.verification.weight_type` OR `request_id.shipment.weight_type` OR `shipment.weight_type`
- **Volumetric Weight**: `verification.total_vm` OR `verification.volumetric_weight` OR `request_id.verification.total_vm` OR `request_id.shipment.volumetric_weight`
- **Chargeable Weight**: `verification.chargeable_weight` OR `request_id.verification.chargeable_weight` OR `request_id.shipment.chargeable_weight`
- **Calculated Rate**: `verification.calculated_rate` OR `request_id.verification.calculated_rate` OR `base_rate` OR `request_id.base_rate`

### 3. Database Query
Use MongoDB aggregation or populate to:
1. Find the invoice request by ID
2. Populate/join verification data
3. Populate/join request_id data (if exists)
4. Populate/join booking data (if exists)
5. Ensure all nested objects are fully populated

### 4. Performance Considerations
- Use efficient aggregation pipelines
- Only fetch necessary fields (but ensure all verification fields are included)
- Consider caching if appropriate (but frontend will disable cache for this endpoint)

## Frontend Integration

The frontend will:
1. Call this endpoint when "View" button is clicked
2. Show loading state while fetching
3. Display all returned data in the shipment details dialog
4. Fallback to cached data if API fails

## Important Notes

- This endpoint should NOT filter or exclude any verification data
- All weight calculations should be included
- All box details should be included
- The response should match the structure expected by the frontend
- Ensure Decimal128 values are properly converted to numbers in the response
