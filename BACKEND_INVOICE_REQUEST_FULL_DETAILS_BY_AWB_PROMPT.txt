BACKEND PROMPT: Create Endpoint to Fetch Full Invoice Request Details by AWB

========================================
REQUIREMENT
========================================
Create a new API endpoint that fetches COMPLETE invoice request details by AWB number. This endpoint should be used when the user opens the verification form or needs full details for a specific invoice request.

========================================
ENDPOINT SPECIFICATION
========================================

Endpoint: GET /api/invoice-requests/by-awb/:awb

Parameters:
- awb (URL parameter): The AWB number, tracking code, or invoice number to search for

Query Parameters (optional):
- includeBooking: boolean (default: true) - Include full booking data
- includeVerification: boolean (default: true) - Include full verification data
- includeRequestId: boolean (default: true) - Include full request_id data

========================================
SEARCH LOGIC
========================================
The endpoint should search for invoice requests matching the AWB parameter in the following order:
1. tracking_code (exact match)
2. awb_number (exact match)
3. awb (exact match)
4. invoice_number (exact match)

If multiple matches are found, return the most recent one (by createdAt descending).

========================================
POPULATION REQUIREMENTS
========================================
- Populate ALL nested objects (booking, request_id, verification, etc.)
- Include ALL fields from related collections
- Do NOT use field filtering for this endpoint (return complete data)
- Ensure all Decimal128 fields are properly formatted

========================================
PERFORMANCE CONSIDERATIONS
========================================
- This endpoint is called only when user opens verification form (not on every page load)
- It's acceptable to be slightly slower since it's user-initiated
- Use MongoDB aggregation pipeline for efficient data retrieval
- Cache the result for 30 seconds to handle multiple rapid requests

========================================
EXAMPLE USAGE
========================================
GET /api/invoice-requests/by-awb/AWB123456
GET /api/invoice-requests/by-awb/AWB123456?includeBooking=true&includeVerification=true

========================================
IMPLEMENTATION NOTES
========================================
1. This endpoint should NOT be paginated (returns single document)
2. Should handle case-insensitive AWB matching
3. Should handle partial AWB matches if exact match not found (optional)
4. Should return 404 if no invoice request found with that AWB
5. Should include proper error handling for invalid AWB formats
