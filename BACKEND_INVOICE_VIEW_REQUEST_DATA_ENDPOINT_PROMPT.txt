GOAL
Implement a single backend endpoint that powers the Finance System "Invoices → View Request Data" button.
The endpoint must return data combined from BOTH collections:
- invoices
- invoicerequests (a.k.a. invoiceRequests / invoice-requests collection)

Endpoint (NEW)
GET /invoices-unified/:invoiceId/request-data

High-level behavior
1) Fetch the invoice document from the invoices collection using :invoiceId.
2) Extract the related invoiceRequest id from the invoice document.
3) Fetch the invoiceRequest document from invoicerequests using that id.
4) Return BOTH sources to frontend in a single response:
{
  "success": true,
  "data": {
    "invoice": { ... },
    "invoiceRequest": { ... } // can be null if not found
  }
}

Why
The frontend "View Request Data" dialog must render request details from invoicerequests (booking snapshot + verification),
but also needs invoice-side fields (invoice number, AWB, charges, etc.) as the authoritative financial source.

====================================================================
REQUEST / RESPONSE CONTRACT
====================================================================

Request
- Path param: invoiceId (string)

Success response (200)
{
  "success": true,
  "data": {
    "invoice": { /* invoice fields from invoices collection */ },
    "invoiceRequest": { /* request fields from invoicerequests collection */ }
  }
}

If invoiceRequest is not found (still 200)
{
  "success": true,
  "data": {
    "invoice": { /* invoice */ },
    "invoiceRequest": null
  }
}

Error responses
- 404 if invoice is not found:
{ "success": false, "error": "Invoice not found" }
- 400 if invoiceId is invalid:
{ "success": false, "error": "Invalid invoiceId" }

====================================================================
LINKING RULE (HOW TO FIND THE REQUEST)
====================================================================

From the invoice document, determine invoiceRequestId using the first available:
1) invoice.request_id._id   (if request_id is populated)
2) invoice.request_id       (if request_id is an ObjectId/string)
3) invoice.invoice_request_id
4) invoice.requestId / invoice.invoiceRequestId (only if your backend uses camelCase)

NOTE: This endpoint should NOT rely on embedded request data inside the invoice payload.
It must fetch the fresh invoicerequests document from the database.

====================================================================
FETCH ONLY REQUIRED FIELDS (PROJECTIONS)
====================================================================

The frontend dialog displays the following (current implementation):
- Request header: Request ID, Invoice Number, AWB/Tracking Code, Reference Number, Service Code, Status, Cargo Service, Agent Name
- Sender: name, phone, email, country, full address, deliveryOption
- Receiver: name, phone, email, country, full address, deliveryOption
- Shipment & Verification: weights (actual/volumetric/chargeable/total), boxes, weight_type, classification, rate_bracket, amount/calculated_rate
- Insurance: insured flag, declared_value
- Additional: verification_notes, listed_commodities, booking notes/additionalDetails, verified timestamps (if present)

Use MongoDB projections to fetch ONLY what is required.

IMPORTANT
- Do not fetch entire documents without projection (performance).
- Do not populate big arrays/documents unnecessarily; only include what the dialog renders.
- This endpoint is called on-demand (when user opens the dialog), so it can return richer data than list endpoints, but still should be projected.

====================================================================
REFERENCE IMPLEMENTATION (PSEUDOCODE)
====================================================================

// Express-style example
router.get('/invoices-unified/:invoiceId/request-data', async (req, res) => {
  const { invoiceId } = req.params;

  // 1) Validate invoiceId
  if (!ObjectId.isValid(invoiceId)) {
    return res.status(400).json({ success: false, error: 'Invalid invoiceId' });
  }

  // 2) Fetch invoice with projection
  const invoice = await db.collection('invoices').findOne(
    { _id: new ObjectId(invoiceId) },
    { projection: INVOICE_PROJECTION }
  );
  if (!invoice) {
    return res.status(404).json({ success: false, error: 'Invoice not found' });
  }

  // 3) Extract invoiceRequestId
  const invoiceRequestId =
    invoice?.request_id?._id ||
    invoice?.request_id ||
    invoice?.invoice_request_id ||
    invoice?.requestId ||
    invoice?.invoiceRequestId;

  // 4) Fetch invoiceRequest with projection
  let invoiceRequest = null;
  if (invoiceRequestId && ObjectId.isValid(invoiceRequestId.toString())) {
    invoiceRequest = await db.collection('invoicerequests').findOne(
      { _id: new ObjectId(invoiceRequestId.toString()) },
      { projection: INVOICE_REQUEST_PROJECTION }
    );
  }

  // 5) Return both sources
  return res.status(200).json({
    success: true,
    data: { invoice, invoiceRequest }
  });
});
