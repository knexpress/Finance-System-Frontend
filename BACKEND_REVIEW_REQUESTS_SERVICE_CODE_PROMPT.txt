BACKEND: Include Service Code in Review Requests API Response
================================================================

REQUIREMENT:
------------
The review-requests page needs to display dynamic shipment status labels based on the service type (PH to UAE vs UAE to PH). The frontend needs the `service_code` field to determine which labels to show.

CURRENT API ENDPOINT:
---------------------
GET /api/bookings/verified-invoices

This endpoint returns bookings that have verified invoices for the cargo status management page.

REQUIRED CHANGES:
-----------------

1. **Include `service_code` in API Response:**
   The booking objects returned by `/api/bookings/verified-invoices` must include the `service_code` field.

   The service_code can be found in multiple locations:
   - `booking.service_code`
   - `booking.service`
   - `booking.request_id.service_code`
   - `booking.request_id.service`
   - `booking.booking_id.service_code` (if booking references another booking)

2. **Response Structure:**
   Each booking object should include:
   ```json
   {
     "_id": "...",
     "awb": "...",
     "customer_name": "...",
     "receiver_name": "...",
     "service_code": "PH_TO_UAE" | "UAE_TO_PH" | "PH_TO_UAE_EXPRESS" | "UAE_TO_PH_STANDARD" | etc.,
     "shipment_status": "...",
     "batch_no": "...",
     "invoice_number": "...",
     "sender": {
       "completeAddress": "...",
       "country": "..."
     },
     "receiver": {
       "completeAddress": "...",
       "country": "..."
     },
     ...
   }
   ```

3. **Service Code Normalization:**
   The service_code should be normalized to uppercase with underscores (e.g., "PH_TO_UAE", "UAE_TO_PH").
   Common variations to handle:
   - "ph-to-uae", "PH-TO-UAE", "ph_to_uae" → "PH_TO_UAE"
   - "uae-to-ph", "UAE-TO-PH", "uae_to_ph" → "UAE_TO_PH"
   - "uae-to-pinas", "UAE_TO_PINAS" → "UAE_TO_PH"
   - Variations with "_EXPRESS", "_STANDARD" suffixes should be preserved

4. **Fallback Logic:**
   If service_code is not directly available on the booking, check:
   - Related request document (`request_id.service_code`)
   - Related booking document (`booking_id.service_code`)
   - Service field if service_code doesn't exist

EXAMPLE BACKEND IMPLEMENTATION:
--------------------------------

```javascript
// GET /api/bookings/verified-invoices
router.get('/bookings/verified-invoices', authenticateToken, async (req, res) => {
  try {
    // Find bookings with verified invoices
    const bookings = await Booking.find({
      invoice_id: { $exists: true, $ne: null },
      // Add any other filters needed
    })
    .populate('request_id', 'service_code service')
    .populate('booking_id', 'service_code service')
    .lean();

    // Map bookings to include service_code and default shipment_status
    const bookingsWithService = bookings.map(booking => {
      // Get service_code from various possible locations
      const serviceCode = 
        booking.service_code ||
        booking.service ||
        booking.request_id?.service_code ||
        booking.request_id?.service ||
        booking.booking_id?.service_code ||
        booking.booking_id?.service ||
        null;

      // Normalize service code
      const normalizedServiceCode = serviceCode
        ? String(serviceCode).toUpperCase().replace(/[\s-]+/g, '_')
        : null;

      // Set default shipment_status if missing
      const shipmentStatus = booking.shipment_status || 'SHIPMENT_RECEIVED';

      return {
        ...booking,
        service_code: normalizedServiceCode,
        shipment_status: shipmentStatus, // Always include, default to SHIPMENT_RECEIVED
        // Include other required fields
        customer_name: booking.customer_name || booking.request_id?.customer?.name,
        receiver_name: booking.receiver_name || booking.request_id?.receiver?.name,
        sender: booking.sender || booking.request_id?.sender,
        receiver: booking.receiver || booking.request_id?.receiver,
        // ... other fields
      };
    });

    res.json({
      success: true,
      data: bookingsWithService
    });
  } catch (error) {
    console.error('Error fetching bookings with verified invoices:', error);
    res.status(500).json({
      success: false,
      error: 'Failed to fetch bookings'
    });
  }
});
```

FRONTEND USAGE:
---------------
The frontend will use the service_code to dynamically display:
- **PH to UAE services:**
  - "Departed from Manila"
  - "In Transit going to Dubai Airport"
  - "Arrived at Dubai Airport"

- **UAE to PH services:**
  - "Departed from UAE"
  - "In Transit going to Manila Airport"
  - "Arrived at Manila Airport"
