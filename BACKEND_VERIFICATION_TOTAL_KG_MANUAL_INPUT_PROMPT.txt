BACKEND PROMPT: Add Manual Total Kilograms Field to Verification System

PRIORITY: HIGH - Required for Finance Invoice Generation Accuracy

================================================================================
REQUIREMENT OVERVIEW
================================================================================

The Operations verification form now includes a manual "Total Kilograms" field that 
must be stored and used by the Finance department for accurate invoice generation.

KEY POINTS:
1. Operations can manually input "Total Kilograms" (total_kg) during verification
2. Operations can manually input "Total Number of Boxes" (number_of_boxes) - already exists
3. Volumetric Weight (VW) vs Actual Weight (AW) remains SYSTEM-CALCULATED
4. Finance invoice generation must use the manual total_kg value when available

================================================================================
CURRENT STATE
================================================================================

The verification system currently stores:
- actual_weight: Manual input for actual weight
- volumetric_weight: Manual input for volumetric weight  
- chargeable_weight: System-calculated (higher of actual_weight or volumetric_weight)
- weight_type: System-determined ('ACTUAL' or 'VOLUMETRIC')
- number_of_boxes: Manual input (already exists)

================================================================================
NEW REQUIREMENT
================================================================================

Add a new field to the verification data structure:
- total_kg: Manual input for total kilograms (separate from actual_weight)
  - Type: Number (Float)
  - Required: Yes
  - Purpose: Used by Finance for invoice generation
  - Note: This is different from actual_weight and chargeable_weight

================================================================================
DATABASE SCHEMA UPDATE
================================================================================

Update the invoice_requests collection verification object to include:

```javascript
verification: {
  // ... existing fields ...
  number_of_boxes: Number,        // Already exists - manual input
  total_kg: Number,               // NEW - manual input for total kilograms
  actual_weight: Number,           // Manual input - used for VW vs AW calculation
  volumetric_weight: Number,       // Manual input - used for VW vs AW calculation
  chargeable_weight: Number,       // System-calculated (higher of actual or volumetric)
  weight_type: String,            // System-determined ('ACTUAL' or 'VOLUMETRIC')
  // ... other fields ...
}
```

================================================================================
API ENDPOINT UPDATES
================================================================================

1. UPDATE VERIFICATION ENDPOINT:
   PUT /api/invoice-requests/:id/verification
   
   Accept new field in request body:
   {
     // ... existing fields ...
     "total_kg": 25.5,  // NEW - required field
     "number_of_boxes": 3,
     // ... other fields ...
   }

2. VALIDATION:
   - total_kg must be a positive number
   - total_kg is required when completing verification
   - total_kg can be different from actual_weight or chargeable_weight

3. RESPONSE:
   Include total_kg in verification object when returning invoice request data

================================================================================
FINANCE INVOICE GENERATION REQUIREMENTS
================================================================================

When Finance generates invoices, the system MUST:

1. PRIORITY ORDER for weight display:
   a) Use verification.total_kg if available (manual input from Operations)
   b) Fallback to verification.chargeable_weight (system-calculated)
   c) Fallback to verification.actual_weight
   d) Fallback to request.weight

2. PRIORITY ORDER for number of boxes:
   a) Use verification.number_of_boxes (manual input from Operations)
   b) Fallback to request.number_of_boxes
   c) Fallback to 1

3. VW vs AW COMPARISON (for display purposes):
   - Continue using verification.actual_weight vs verification.volumetric_weight
   - Display which weight type is being used (ACTUAL or VOLUMETRIC)
   - This is for informational purposes only
   - The invoice amount should use total_kg when available

================================================================================
DATA FLOW
================================================================================

OPERATIONS VERIFICATION:
1. Operations enters:
   - Total Number of Boxes (manual)
   - Total Kilograms (manual) ← NEW
   - Actual Weight (manual) - for VW vs AW calculation
   - Volumetric Weight (manual) - for VW vs AW calculation

2. System calculates:
   - Chargeable Weight = max(actual_weight, volumetric_weight)
   - Weight Type = 'ACTUAL' or 'VOLUMETRIC'

3. System stores:
   - number_of_boxes (manual)
   - total_kg (manual) ← NEW
   - actual_weight (manual)
   - volumetric_weight (manual)
   - chargeable_weight (calculated)
   - weight_type (determined)

FINANCE INVOICE GENERATION:
1. Finance retrieves invoice request
2. System uses:
   - total_kg for invoice weight (if available)
   - number_of_boxes for invoice boxes (if available)
   - actual_weight vs volumetric_weight for display/comparison only
